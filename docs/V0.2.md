# v0.2 Contract — Parameterized Families & Stratification

## One-sentence goal

Given a **Lie algebra family** with structure constants in a polynomial or
rational function ring over a base field (tests on \(\mathbb{Q}[a,b,\ldots]\) /
\(\mathbb{Q}(a,b,\ldots)\)), **compute classical invariants generically** and
**certify the exceptional loci** where those invariants jump — i.e. produce a
**parameter stratification** with inspectable certificates, not only “generic dim”.

This is the project’s first durable differentiator versus “another Lie algebra
CAS”: *where does structure change, and why?*

**Depends on:** v0.1 symbolic core ([docs/V0.1.md](V0.1.md)) — every stratum
should eventually specialize to a concrete `LieAlgebra` that `analyze` already
understands.

---

## The hidden core: conditional exact linear algebra

Polynomial structure constants alone are **not** the hard part. Almost every
v0.1 algorithm (center, series, Killing radical, Der, Levi corrections,
commutant nullspaces) is **exact linear algebra** over the coefficient domain.

Over a field \(F\), Gaussian elimination is deterministic: a pivot is either
zero or a unit. Over a **parameter ring / function field**, a pivot expression
such as \(a - b\) forces a **case split**:

\[
a - b \neq 0 \qquad\text{vs}\qquad a - b = 0.
\]

That branch is exactly where structural invariants can jump. The computational
heart of stratification is therefore:

> **Assumption-aware (conditional) exact linear algebra** — track a set of
> polynomial conditions (open inequalities / closed equalities), perform
> elimination under those assumptions, and emit **pivot certificates** when a
> new condition is required.

Without this module, “generic analysis” is incomplete (it silently assumes all
encountered pivots are nonzero), and “stratification” cannot be certified.

```
structure constants in F[a] or Frac(F[a])
        │
        ▼
 conditional GE / nullspace / rank
   (assumptions Σ; pivot p; branch Σ∧(p≠0) | Σ∧(p=0))
        │
        ├── generic leaf: invariants under Σ_generic
        └── exceptional leaves: refine Σ, recurse
                │
                ▼
        stratification tree + certificates
```

## Relationship to v0.1

| v0.1 | v0.2 |
|------|------|
| Coefficient **field** \(F\) | Coefficient **ring / field of fractions** in parameters |
| Single algebra \(L\) | Family \(L_{\mathbf{a}}\) |
| `analyze(L)` summary + cached certificates | `analyze` / `stratify` over parameters; per-stratum specialize → v0.1 |
| Rank / dim are numbers | Rank / dim are **piecewise** constants on strata |
| Bases are matrices over \(F\) | Bases are matrices over \(F(\mathbf{a})\) or specialized over \(F\) |

**Reuse, do not fork:** center / series / Killing / Der / Levi should call the
same *mathematical* pipelines, with the scalar arithmetic and linear algebra
backend swapped for a conditional one.

## Engineering milestones

Suggested ship order. Each milestone has a clear deliverable and an explicit
difficulty; later ones depend on earlier ones.

### v0.2.1 — Polynomial / rational-function structure constants

**Contract:** [docs/V0.2.1.md](V0.2.1.md)

**Goal:** Free-parameter coefficient domains \(R = k[a_i]\) and \(K = \mathrm{Frac}(R)\);
exact bracket + Jacobi **identity** testing (residual certificates; no root-finding).

**Deliverable**

> Construct \(L_{a,b}\) over \(R\) or \(K\); if Jacobi holds identically → identity
> certificate; else → explicit nonzero residual (and domain \(q\neq 0\) over \(K\)).

**Non-goal:** solving residuals, stratification, case splitting (later milestones).
---

### v0.2.2 — Specialization + generic field-of-fractions analysis

**Goal:** Move between the family and concrete fibers; run v0.1 invariants
**generically** over \(F(\mathbf{a})\).

**Tasks**

- `specialize(L, Dict(a => α, …)) → LieAlgebra` over the base field (v0.1).
- Generic analysis: treat coefficients in \(\mathrm{Frac}(F[\mathbf{a}])\) as a
  field and call center / Killing / Der / … with ordinary field GE.
- Document the semantics: results are valid on the **open** set where all
  denominators and all pivots encountered during that particular run are
  nonzero — but those pivots are **not yet** collected as certificates
  (that is v0.2.3).

**Hard parts**

- “Generic” is algorithm-dependent if pivots are not logged: two code paths
  might implicitly assume different opens.
- Specialization must respect Jacobi (or re-check) and fail loudly on poles
  (denominator zero).

**Deliverable**

> `analyze_generic(L)` (or `analyze(L)` on a Frac coefficient algebra) plus
> `specialize` round-trip tests against known fibers (e.g. Bianchi / one-param
> deformations of Heisenberg / \(\mathfrak{sl}_2\)).

**North-star UX (partial)**

```julia
R, (a,) = polynomial_ring(QQ, [:a])
L = LieAlgebra(fraction_field(R), …)   # family
analyze(L)          # generic summary over QQ(a)
analyze(specialize(L, Dict(a => 0)))  # fiber = v0.1 report
```

### v0.2.3 — Assumption-aware linear algebra  ★ core

**Goal:** Replace “silent” GE with a backend that carries an assumption set
\(\Sigma\) and emits pivot obligations.

**Tasks**

- Assumption language: conjunction of polynomial equalities \(f_i = 0\) and
  non-vanishing conditions \(g_j \neq 0\) (start with principal / square-free
  generators; keep the API ring-agnostic).
- Primitive ops under \(\Sigma\): rank, nullspace, solve, rref — each may
  **request a split** on a pivot polynomial \(p\notin\Sigma\).
- Pivot policy hooks: “generic branch first” (\(p \neq 0\)), or interactive /
  exhaustive split.
- Certificate objects: which pivot, which matrix row/col, which assumption
  set before/after.

**Hard parts (the real v0.2 risk)**

- Consistency of \(\Sigma\): \(f=0\) and \(f\neq 0\) must be detected; ideal
  membership / gcd / Groebner may be needed even for mild multivariate cases.
- Expression swell: pivots in \(\mathbb{Q}(a,b)\) grow fast; need
  normalization (content, monic, fraction-free GE / Bareiss where possible).
- Non-principal ideals: zero-set geometry is harder than single-polynomial
  loci; v0.2 may restrict early demos to **one parameter** or **hypersurface
  loci** while designing for several parameters.
- Replaying v0.1 algorithms on top without rewriting each by hand —
  inject the backend at the matrix layer.

**Deliverable**

> A conditional nullspace / rank API used by at least one invariant (recommended
> first client: **center** or **Killing rank**), with tests that force a known
> pivot \(a\) or \(a-b\) and record both branches.

**Success criterion**

> Encountering pivot \(a-b\) does **not** invent an answer; it produces an
> explicit branch certificate.

---

### v0.2.4 — Exceptional-locus certificates

**Goal:** Turn pivot branches into mathematical objects the user can read:
“invariant \(I\) jumps on \(V(p)\) (minus lower-dimensional noise).”

**Tasks**

- Package a completed computation as: generic value + list of exceptional
  polynomials (or ideals) with **which invariant** failed to stay constant.
- Attach witnesses: e.g. center dimension is \(1\) generically but \(2\) when
  \(a=0\), with explicit bases on each side (after specialization).
- Connect to specialization: each closed condition \(\Sigma_\mathrm{closed}\)
  yields a specialized algebra (or a residual family if free parameters remain).

**Hard parts**

- Minimality: raw pivots are not unique; reduce / square-free / primary
  decompose lightly enough to be honest without building a full algebraic
  geometry stack.
- Completeness vs cost: logging pivots from one algorithm (Killing) does not
  automatically give loci for Der; decide a **standard invariant suite** whose
  collective pivots define the stratification used in demos.

**Deliverable**

> `ExceptionalLocus` / similar certificate type: polynomial (ideal), affected
> invariant, generic vs special values, optional specialized report.

---

### v0.2.5 — Recursive parameter stratification

**Goal:** Explore the branch tree systematically and return a stratification
of parameter space.

**Tasks**

- Depth-first or policy-driven recursion: on each split, refine \(\Sigma\),
  recompute the invariant suite, stop when leaf invariants stabilize or
  parameters are fully specialized.
- Output: a tree or list of **strata** — each with assumption set, invariant
  summary (compatibly with v0.1 `LieAlgebraReport` fields), and links to
  certificates from v0.2.3–0.2.4.
- Guardrails: max depth, max degree, “generic-only” mode, one-parameter
  specializations first.

**Hard parts**

- Combinatorial explosion of branches; need pruning when \(\Sigma\) is
  inconsistent or when a locus is empty over the base field.
- Ordering of pivots changes the tree shape but should not change the
  **partition** of parameter space up to refining/coarsening — needs tests.
- Multivariate constructible sets: represent strata as
  \(V(I) \setminus \bigcup V(g_j)\) carefully.

**Deliverable**

> `stratify(L; invariants=…)` → stratification object; pretty summary analogous
> to the north-star example in the project overview (generic region vs \(a=0\)).

---

### v0.2.6 — Invariant comparison across strata

**Goal:** Make strata *comparable* and research-usable: what jumped, what stayed,
how fibers relate.

**Tasks**

- Diff reports: `compare(stratum_i, stratum_j)` on dims / flags (center,
  solvability, Killing rank, Der dim, Levi kind, simple-factor dims, …).
- Optional: attempt to match bases / embeddings after specialization (best
  effort; isomorphism helpers can stay shallow in v0.2).
- Fixture suite: known one-parameter families with hand-documented strata
  (Bianchi-type, parametric Heisenberg, \(\mathfrak{sl}_2\) deformations, …).
- Property tests: specialize a generic point in an open stratum → v0.1
  `analyze` agrees with the stratum summary; specialize on a locus → agrees
  with the exceptional leaf.

**Hard parts**

- Defining “the same” invariant when presentations differ (basis change in
  the fiber).
- Avoiding false jumps from denormalized pivots (same geometric locus,
  different generators).

**Deliverable**

> Stratification fixtures + comparison API; README / example script showing a
> nontrivial family and its jump table.

## UX sketch (end of v0.2)

```julia
R, (a, b) = polynomial_ring(QQ, [:a, :b])
K = fraction_field(R)
L = LieAlgebra(K, n, Dict(
    (1, 2) => [0, 0, a],          # illustrative
    # …
))

S = stratify(L)                   # uses conditional LA + invariant suite
show(S)
# Generic region (a ≠ 0, a ≠ b, …):
#   center dim = 0, Killing rank = …, Der dim = …
# a = 0:
#   center dim = 1, …
# a = b (a ≠ 0):
#   …

analyze(specialize(L, Dict(a => 0, b => 1)))  # v0.1 report on a fiber
```

Printed summaries stay **basis-invariant** (dims / flags / factor-dim lists),
matching the v0.1 `analyze` philosophy; bases live in detail certificates.

## Testing philosophy (extends v0.1)

1. **Hand families** — one-parameter examples with known jumps.
2. **Fiber agreement** — random/`QQ` points in a stratum match specialized
   `analyze`.
3. **Pivot honesty** — forced \(a-b\) (or \(a\)) splits appear in certificates.
4. **Basis-change in fibers** — specialized invariants remain stable under
   `change_of_basis` (v0.1 property).
5. **Idempotence / refinement** — re-stratifying under a coarser invariant
   suite coarsens strata; finer suite refines without contradicting dims.

Differential checks vs Sage/Oscar can wait until 0.2.5+ for selected families.

## Success criterion for “v0.2 done”

1. User can define \(L_{\mathbf{a}}\) with polynomial/rational structure constants.
2. Generic analysis and specialization interoperate with v0.1 `analyze`.
3. Conditional linear algebra **certifies** pivots; stratification is built from
   those certificates, not from ad-hoc substitutions alone.
4. At least one nontrivial multi-branch example (preferably multivariate or
   one-param with ≥2 exceptional hypersurfaces) ships under `example/` and
   `fixtures/`.
5. Cross-stratum comparison answers: *what jumped?* with dims/flags.

---

## Recommended implementation order (practical)

1. **0.2.1** types + Jacobi over \(\mathbb{Q}(a)\).
2. **0.2.2** `specialize` + generic `analyze` (accept “unguarded” GE briefly).
3. **0.2.3** conditional nullspace; retrofit **center** and **Killing rank**.
4. **0.2.4** locus certificates from those two invariants.
5. **0.2.5** `stratify` recursion on the standard suite (center, Killing,
   solvability via Cartan or derived length, Der dim).
6. **0.2.6** compare + fixtures + example script.

Levi / ideal decomposition over parameters can follow once rank/nullspace are
trustworthy under \(\Sigma\); they are excellent stress clients but should not
block the first stratification demos.

---

## Guiding principles (v0.2-specific)

- **Branch explicitly** — never swallow a parameter pivot.
- **Certificates over samples** — a polynomial locus beats 100 random trials.
- **Specialize to v0.1** — every leaf should be checkable by the concrete core.
- **Fraction-free where possible** — control swell early.
- **One parameter first, design for many** — multivariate geometry is opt-in
  complexity, not the first demo blocker.
